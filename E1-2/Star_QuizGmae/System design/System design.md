# 별자리 퀴즈 게임 시스템 설계

## 1. 설계 목표

이 프로젝트는 Python 표준 라이브러리만 사용해 터미널에서 실행되는 별자리 퀴즈 게임을 구현한다. 다음 원칙을 기준으로 설계한다.

- 최소 5개의 객관식 퀴즈를 제공한다.
- 퀴즈 풀기, 퀴즈 추가, 목록 보기, 최고 점수 확인, 종료 기능을 제공한다.
- 퀴즈 목록과 최고 점수를 프로젝트 루트의 `state.json`에 UTF-8로 저장한다.
- 잘못된 입력이나 저장 파일 오류가 발생해도 프로그램이 비정상 종료되지 않게 한다.
- 작은 프로젝트 규모에 맞게 책임은 분리하되 클래스를 지나치게 세분화하지 않는다.

## 2. 요구사항 추적표

| 요구사항 | 담당 구성 요소 | 설계 방법 |
|---|---|---|
| 메뉴 출력과 기능 선택 | `QuizGame.run()` | 종료를 선택할 때까지 메뉴 반복 |
| 잘못된 숫자 입력 처리 | `QuizGame.read_number()` | 공백·빈 값·변환 실패·범위 검사 후 재입력 |
| 퀴즈 문제 표현 | `Quiz` | 문제, 선택지 4개, 정답 번호를 속성으로 관리 |
| 기본 퀴즈 5개 이상 | 기본 데이터 생성 함수 | `state.json`이 없거나 손상되면 사용 |
| 퀴즈 풀기 | `QuizGame.play()` | 문제 출력, 답 입력, 정답 판정, 최종 점수 계산 |
| 퀴즈 추가 | `QuizGame.add_quiz()` | 문제·선택지 4개·정답을 검증하고 즉시 저장 |
| 퀴즈 목록 | `QuizGame.show_quizzes()` | 저장된 문제를 번호와 함께 출력 |
| 최고 점수 | `QuizGame.show_best_score()` | 미응시 상태와 기존 최고 점수를 구분해 출력 |
| 데이터 저장·불러오기 | `Storage` | JSON 변환, UTF-8 입출력, 파일 예외 처리 |
| 안전한 종료 | `QuizGame.run()` | 정상 종료 및 `KeyboardInterrupt`, `EOFError` 처리 |
| Git 이력 | Git 저장소 | 기능 단위 커밋, 브랜치 생성·병합, clone·pull 실습 |
| 프로젝트 설명 | `README.md` | 개요, 주제 선정 이유, 실행법, 기능, 파일 구조, JSON 설명 |

## 4. 구성 요소와 책임

### 4-1. `main.py`

프로그램의 시작점이다.

- `Storage`를 생성한다.
- 저장 데이터를 불러온다.
- `QuizGame`을 생성하고 `run()`을 호출한다.
- 구체적인 메뉴 처리나 게임 규칙은 포함하지 않는다.

```python
def main() -> None:
    storage = Storage("state.json")
    quizzes, best_score = storage.load()
    game = QuizGame(quizzes, best_score, storage)
    game.run()
```

### 4-2. `Quiz`

객관식 문제 한 개의 데이터와 문제 자체에 관련된 동작을 담당한다.

#### 속성

| 속성 | 자료형 | 규칙 |
|---|---|---|
| `question` | `str` | 공백이 아닌 문제 문장 |
| `choices` | `list[str]` | 공백이 아닌 선택지 정확히 4개 |
| `answer` | `int` | 사용자에게 표시되는 번호와 같은 `1~4` |

#### 메서드

```text
__init__(question: str, choices: list[str], answer: int)
display() -> None
is_correct(selected_answer: int) -> bool
to_dict() -> dict
from_dict(data: dict) -> Quiz
```

- `display()`: 문제와 번호가 붙은 선택지 4개를 출력한다.
- `is_correct()`: 입력 번호가 정답 번호와 같은지 반환한다.
- `to_dict()`: JSON 저장이 가능한 딕셔너리로 변환한다.
- `from_dict()`: 불러온 딕셔너리를 검증해 `Quiz` 객체로 변환한다.

정답 번호는 전체 구현에서 `1~4`를 사용한다. 화면 번호와 내부 값이 같으므로 변환 과정의 실수를 줄일 수 있다.

### 4-3. `QuizGame`

게임 전체 흐름과 사용자 상호작용을 조율한다.

#### 속성

| 속성 | 자료형 | 의미 |
|---|---|---|
| `quizzes` | `list[Quiz]` | 현재 저장된 퀴즈 목록 |
| `best_score` | `int \| None` | 최고 정답 수. 미응시는 `None` |
| `storage` | `Storage` | 데이터 저장을 요청할 객체 |

#### 메서드

```text
run() -> None
show_menu() -> None
read_number(prompt: str, minimum: int, maximum: int) -> int
read_non_empty(prompt: str) -> str
play() -> None
add_quiz() -> None
show_quizzes() -> None
show_best_score() -> None
save_state() -> None
```

- `run()`: 메뉴를 반복 출력하고 선택한 기능으로 분기한다.
- `read_number()`: 숫자 입력에 공통 검증 규칙을 적용한다.
- `read_non_empty()`: 문제와 선택지에서 빈 입력을 막는다.
- `play()`: 전체 퀴즈를 출제하고 점수와 최고 점수를 계산한다.
- `add_quiz()`: 입력받은 퀴즈를 목록에 추가한 뒤 저장한다.
- `show_quizzes()`: 문제 번호, 문제 문장과 선택지를 출력한다.
- `show_best_score()`: 미응시 여부 또는 최고 점수를 출력한다.
- `save_state()`: 현재 퀴즈와 최고 점수를 `Storage`에 전달한다.

### 4-4. `Storage`

게임 로직과 파일 형식을 분리하고 JSON 저장·불러오기와 복구를 담당한다.

#### 속성

| 속성 | 자료형 | 의미 |
|---|---|---|
| `path` | `str` | 저장 파일 경로. 기본값은 프로젝트 루트의 `state.json` |

#### 메서드

```text
__init__(path: str)
load() -> tuple[list[Quiz], int | None]
save(quizzes: list[Quiz], best_score: int | None) -> None
create_default_quizzes() -> list[Quiz]
```

- `load()`: 파일을 읽고 데이터 구조를 검증한 뒤 객체로 변환한다.
- `save()`: 객체를 딕셔너리로 변환하여 UTF-8 JSON으로 저장한다.
- `create_default_quizzes()`: 최소 5개의 별자리 퀴즈를 반환한다.

파일이 없거나 손상된 경우 안내 메시지를 출력하고 기본 퀴즈와 `None` 점수로 복구한다. 복구 데이터는 사용자가 데이터를 변경하거나 종료할 때 저장한다. 읽기 오류가 발생했다는 사실을 숨기지 않고 사용자에게 알린다.

## 5. 데이터 설계

### 5-1. `state.json` 스키마

```json
{
  "quizzes": [
    {
      "question": "사자자리의 영어 이름은?",
      "choices": ["Leo", "Gemini", "Pisces", "Aries"],
      "answer": 1
    }
  ],
  "best_score": null
}
```

### 5-2. 데이터 규칙

- 최상위 값은 객체이며 `quizzes`, `best_score` 키를 가진다.
- `quizzes`는 퀴즈 객체의 배열이다.
- 각 퀴즈는 `question`, `choices`, `answer`를 가진다.
- `choices`에는 문자열 4개만 저장한다.
- `answer`는 `1~4`의 정수로 저장한다.
- 게임을 한 적이 없으면 `best_score`는 `null`, 이후에는 0 이상의 정수이다.
- 저장할 때 `ensure_ascii=False`, `indent=2`를 사용한다.

일부 퀴즈 또는 최고 점수의 형식이 규칙과 다르면 파일 전체를 신뢰하지 않고 기본 데이터로 복구한다. 첫 구현에서는 부분 복구보다 예측 가능한 전체 복구를 선택한다.

## 6. 실행 흐름

### 6-1. 프로그램 전체 흐름

```text
프로그램 시작
  → state.json 불러오기
  → 파일 없음·손상 시 기본 데이터로 복구
  → QuizGame 생성
  → 메뉴 출력 및 입력 검증
  → 선택한 기능 실행
  → 데이터 변경 시 저장
  → 종료 선택 시 현재 상태 저장 후 정상 종료
```

### 6-2. 퀴즈 풀기 흐름

```text
퀴즈 존재 여부 확인
  → 각 퀴즈의 문제와 선택지 출력
  → 1~4 범위의 정답 입력
  → 정답·오답 안내 및 점수 계산
  → 최종 점수 출력
  → 기존 최고 점수와 비교
  → 최고 점수 갱신 시 저장
```

퀴즈가 없으면 게임을 시작하지 않고 안내 후 메뉴로 돌아간다. 기본 데이터가 있으므로 정상 상황에서는 퀴즈가 존재하지만, 빈 데이터도 안전하게 처리한다.

### 6-3. 퀴즈 추가 흐름

```text
빈 값이 아닌 문제 입력
  → 빈 값이 아닌 선택지 4개 입력
  → 1~4 범위의 정답 번호 입력
  → Quiz 객체 생성
  → quizzes에 추가
  → state.json 저장
  → 등록 완료 메시지 출력
```

## 7. 입력 및 예외 처리 정책

### 7-1. 숫자 입력

모든 숫자 입력은 다음 순서로 처리한다.

1. `strip()`으로 앞뒤 공백을 제거한다.
2. 빈 입력이면 안내 후 다시 입력받는다.
3. `int()` 변환에서 `ValueError`가 발생하면 안내 후 다시 입력받는다.
4. 허용 범위를 벗어나면 안내 후 다시 입력받는다.

예를 들어 메뉴가 `1~5`라면 `9`, 정답이 `1~4`라면 `0`을 허용하지 않는다. `" 1 "`은 공백을 제거한 뒤 정상 입력으로 처리한다.

### 7-2. 문자열 입력

문제와 선택지에는 `strip()`을 적용한다. 빈 문자열은 저장하지 않고 안내 후 다시 입력받는다.

### 7-3. 프로그램 종료 입력

`QuizGame.run()`에서 `KeyboardInterrupt`와 `EOFError`를 처리한다. 가능한 현재 상태를 저장한 뒤 안내 메시지를 출력하고 정상적으로 종료한다.

### 7-4. 파일 오류

| 상황 | 처리 |
|---|---|
| `state.json` 없음 | 기본 퀴즈 5개 이상과 미응시 점수 사용 |
| JSON 문법 손상 | 안내 후 기본 데이터로 복구 |
| 키 또는 값 형식 오류 | 안내 후 기본 데이터로 복구 |
| 읽기 권한·기타 `OSError` | 안내 후 기본 데이터로 실행 |
| 저장 실패 | 실패 사실을 안내하고 프로그램은 가능한 범위에서 계속 실행 |

## 8. 설계 결정과 근거

### 8-1. `Quiz`와 `QuizGame` 분리

`Quiz`는 문제 한 개의 데이터와 정답 판정을 담당하고, `QuizGame`은 여러 문제의 진행과 점수를 관리한다. 문제 표현과 게임 흐름을 분리하면 변경 범위가 명확해진다.

### 8-2. `Storage` 분리

JSON 형식과 파일 예외 처리는 게임 규칙과 다른 책임이다. 이를 분리하면 저장 형식이 바뀌어도 게임 진행 코드를 크게 수정할 필요가 없다.

### 8-3. 메뉴 책임을 `QuizGame`에 배치

`main.py`는 의존 객체를 만들고 프로그램을 시작하는 역할만 한다. 메뉴는 게임의 기능을 선택하는 흐름이므로 `QuizGame.run()`에서 일관되게 관리한다.

### 8-4. 별도 입력 클래스는 만들지 않음

입력 검증은 필요하지만 현재 규모에서는 `InputValidator` 클래스를 추가할 만큼 복잡하지 않다. `QuizGame`의 공통 입력 메서드로 중복을 제거하고, 검증 규칙이 커질 때 별도 모듈로 분리한다.

## 9. 테스트 계획

| 구분 | 테스트 상황 | 기대 결과 |
|---|---|---|
| 메뉴 입력 | `" 1 "` 입력 | 공백 제거 후 1번 기능 실행 |
| 메뉴 입력 | 빈 값, `abc`, `9` 입력 | 안내 후 메뉴 재입력 |
| 정답 입력 | `0`, `5`, 문자 입력 | 안내 후 `1~4` 재입력 |
| 문자열 입력 | 빈 문제 또는 선택지 | 안내 후 해당 값 재입력 |
| 최초 실행 | `state.json` 없음 | 기본 퀴즈 5개 이상으로 실행 |
| 손상 파일 | 잘못된 JSON 저장 | 안내 후 기본 데이터로 복구 |
| 퀴즈 풀이 | 전체 문제 응답 | 정답 수와 최종 점수 출력 |
| 최고 점수 | 기존 점수보다 높은 점수 | 최고 점수 갱신 및 저장 |
| 최고 점수 | 기존 점수 이하 | 기존 최고 점수 유지 |
| 미응시 | 게임 전 점수 확인 | 아직 기록이 없다는 메시지 출력 |
| 퀴즈 추가 | 정상 데이터 등록 후 재실행 | 추가한 퀴즈 유지 |
| 빈 목록 | 퀴즈가 없는 상태에서 풀이·목록 | 안내 후 메뉴로 복귀 |
| 안전 종료 | `Ctrl+C` 또는 EOF 발생 | 안내와 함께 비정상 traceback 없이 종료 |
| 인코딩 | 한글 퀴즈 저장 후 재실행 | 글자가 깨지지 않고 동일하게 출력 |

## 10. Git 작업 계획

기능이 완성되는 순서에 맞춰 의미 단위로 커밋한다.

```text
chore: 프로젝트 기본 파일 구성
feat: Quiz 클래스와 기본 퀴즈 추가
feat: 메뉴와 공통 입력 검증 구현
feat: 퀴즈 풀이 기능 구현
feat: 퀴즈 등록과 목록 기능 구현
feat: 최고 점수 기능 구현
feat: JSON 저장과 복구 기능 구현
fix: 종료 및 예외 처리 보완
docs: README와 설계 문서 작성
```

별도 기능 브랜치에서 한 가지 이상의 기능을 구현한 뒤 `main`에 병합한다. 개발 완료 후 별도 디렉터리에 저장소를 `clone`하고, 간단한 변경을 `push`한 다음 기존 작업 디렉터리에서 `pull`하여 정상 반영되는지 확인한다.

## 11. 완료 기준

- 메뉴의 다섯 기능이 모두 동작한다.
- 별자리 퀴즈가 5개 이상 포함되어 있다.
- `Quiz`, `QuizGame`을 포함해 최소 두 개 이상의 클래스가 사용된다.
- 잘못된 입력 후 프로그램이 종료되지 않고 재입력 흐름으로 돌아간다.
- 파일 없음과 손상 상황에서도 기본 데이터로 실행된다.
- 추가 퀴즈와 최고 점수가 재실행 후에도 유지된다.
- `state.json`이 프로젝트 루트에 UTF-8로 저장된다.
- README 필수 항목과 Git 커밋·브랜치·병합·clone·pull 기록이 갖춰져 있다.
